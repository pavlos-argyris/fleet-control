# Fleet 5.51.6 · Server 2.2.14 · Worker 5.12.6

## Σειρά παράδοσης

Η 5.51.5 / Server 2.2.13 δημοσιεύθηκε και ενεργοποιήθηκε στις 27/10/2026, πριν ξεκινήσει αυτή η διόρθωση. Η παρούσα είναι η ξεχωριστή επόμενη έκδοση που ζήτησε ο χρήστης. Περιλαμβάνει και όλες τις αλλαγές backup, OTA και καταχωρήσεων της 5.51.5.

## HTTP 500 στο αντίγραφο προσωπικού

Η αιτία αναπαράχθηκε στην παραγωγή, χωρίς αλλαγή δεδομένων:

- Η διαδρομή σελιδοποιημένης λήψης και οι πρώτες σελίδες των 28 κατηγοριών απαντούσαν HTTP 200.
- Η διαδρομή /api/server/system-export/delta απαντούσε HTTP 500 όταν υπήρχαν αλλαγές. Η κλήση χωρίς εκκρεμείς αλλαγές απαντούσε 200.
- Το στοχευμένο log της αποτυχημένης κλήσης ανέφερε: D1_ERROR: too many terms in compound SELECT: SQLITE_ERROR. Η συγκεκριμένη καταγραφή είχε CPU 5 ms και χειρισμένο σφάλμα SQL.
- Τεκμηρίωση διάγνωσης: GitHub Actions runs 40425008909 και 40426663016. Καταγράφηκαν μόνο κατάσταση HTTP, Ray ID, πλήθη και το μήνυμα σφάλματος. Δεν αποθηκεύτηκαν στοιχεία προσωπικού, κωδικοί ή περιεχόμενο τιμολογίων στις αναφορές.

Το προηγούμενο ερώτημα ένωνε πολλά SELECT με UNION ALL για τις καταγεγραμμένες εγγραφές μιας σελίδας. Η νέα υλοποίηση χρησιμοποιεί έναν δεσμευμένο πίνακα JSON και json_each. Δεν υπάρχει πλέον σύνθετο SELECT που εξαρτάται από το πλήθος των αλλαγών.

Διατηρούνται:

- Το όριο 20 αλλαγών ανά σελίδα και ο ίδιος αριθμός αιτημάτων.
- Τα αρχικά αναγνωριστικά και οι αριθμοί σειράς που καταγράφηκαν πριν από το ερώτημα, ακόμη και αν στο μεταξύ ενημερωθεί το ημερολόγιο.
- Οι ενημερώσεις και οι ρητές ενδείξεις διαγραφής.
- Το σταθερό όριο της λήψης και η επόμενη σελίδα.
- Η συμβατότητα με τους υπάρχοντες Server και η αντικατάσταση του τοπικού αντιγράφου μόνο αφού ολοκληρωθούν όλες οι σελίδες.

Δεν απαιτείται διαγραφή βάσης, εκκαθάριση δεδομένων ή επαναφορά backup για αυτή τη διόρθωση.

## Διατήρηση αντιγράφων ασφαλείας

Ενισχύεται και ο καθαρισμός παλαιότερων αντιγράφων:

- Στο όριο διατήρησης προσμετρώνται μόνο καταγεγραμμένες επιτυχείς εξαγωγές με πλήρη αναμενόμενα τοπικά αρχεία και αντίγραφο προσωπικού.
- Επιβεβαιώνεται και το αναγνωριστικό αρχείου του παρόχου, ώστε ένα άγνωστο αρχείο με ίδιο όνομα να μην θεωρείται δική μας εξαγωγή.
- Ημιτελή ζεύγη, αποτυχημένες προσπάθειες, εκκρεμείς αποστολές, ελλιπής κάλυψη και διπλά ονόματα δεν εκτοπίζουν καλά αντίγραφα.
- Αρχεία παλιών εκδόσεων χωρίς καταγεγραμμένη επιτυχή εξαγωγή διατηρούνται. Επομένως μπορεί να υπάρχουν περισσότερα από το επιλεγμένο όριο στον φάκελο. Αυτό αναφέρεται και μέσα στην εφαρμογή.
- Η διατήρηση και η προετοιμασία δεν διαγράφουν τα αρχικά PDF/φωτογραφίες των service.

Η ολοκλήρωση εγγραφής στον επιλεγμένο φάκελο και ο ξεχωριστός «Έλεγχος αναγνωσιμότητας» παραμένουν διαφορετικές ενδείξεις. Ο πάροχος αποθήκευσης και η εξωτερική διαθεσιμότητα χρειάζονται έλεγχο στη συσκευή.

## Έλεγχοι

- Νέος έλεγχος καλεί την πραγματική mirrorDelta με SQLite που επιτρέπει μόνο έναν όρο σε σύνθετο SELECT. Αναπαράγει πρώτα την παλιά αποτυχία και ελέγχει 45 εγγραφές σε πολλαπλές σελίδες, ελληνικό κείμενο, διαγραφές, αλλαγή ημερολογίου κατά τη λήψη, περισσότερες κατηγορίες, σταθερό όριο και έλεγχο πρόσβασης.
- Πραγματικός D1/Workers runtime και οι υπόλοιποι έλεγχοι mirror/backup εξακολουθούν να εκτελούνται.
- Νέος πραγματικός Java έλεγχος διατήρησης εξετάζει άγνωστα αρχεία, ημιτελή ζεύγη, εκκρεμότητες, ελλιπή κάλυψη και το όριο διατήρησης.
- Η παραγωγική δημοσίευση ελέγχει πλέον και τα πραγματικά bytes των APK από τα ενεργά URLs, τη συμφωνία τους με την υπογεγραμμένη κατασκευή, τα Web αρχεία και τις διαδρομές αντιγράφου προσωπικού. Η αναφορά περιέχει μόνο τεχνικά πλήθη/καταστάσεις.
- Τα αποτελέσματα του ακριβούς source commit και της παραγωγικής επαλήθευσης αποθηκεύονται στο GitHub Actions. Δεν έγινε backup, restore, διαγραφή ή εγκατάσταση στη συσκευή του χρήστη.

## Εγκατάσταση

Το Web και ο Worker ενεργοποιούνται με τη δημοσίευση. Ενημερώστε τον Server σε 2.2.14 και τον Client σε 5.51.6 για το πλήρες σύνολο αλλαγών. Στον Server επιλέξτε «Επανάληψη αντιγράφου προσωπικού» και παρακολουθήστε το στάδιο. Η διόρθωση του ερωτήματος βρίσκεται στον Worker και παραμένει συμβατή και με τον προηγούμενο Server.

Αν ο παλιός Server περιμένει ακόμη στο OTA, εγκαταστήστε το νέο Server APK πάνω από την υπάρχουσα εφαρμογή, με την ίδια υπογραφή. Μην κάνετε απεγκατάσταση για μια συνηθισμένη ενημέρωση. Το τοπικό backup μέσα στην εφαρμογή δεν αντέχει σε απεγκατάσταση ή εκκαθάριση δεδομένων.

Πλήρης κώδικας όλων των τμημάτων, APK, Web, Worker, build inputs, σημειώσεις και SHA-256 περιλαμβάνονται στην παράδοση GitHub.
