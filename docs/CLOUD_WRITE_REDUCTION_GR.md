Client/Web5.62.1(106), Server2.11.1(76), Worker5.19.1. Δεν αλλάζουν επιχειρησιακά δεδομένα, ιστορικά, οικονομικοί κανόνες, δικαιώματα, αρχικά κλειδιά ή το business fence της D1.

Μετρήσεις σε πραγματικό τοπικό Workerd SQLite-DO με συνθετικά δεδομένα, από `node scripts/measure-cloud-write-cost.mjs`. Μετράται ο τελικός `cursor.rowsWritten` κάθε SQL statement χωριστά, μαζί με τις εγγραφές ευρετηρίων. KV ενέργειες καταγράφονται χωριστά· εδώ οι pointers είναι μικροί. Δεν είναι παραγωγικό billing ή το πραγματικό πλήθος παραγγελιών του ιδιοκτήτη. Η προηγούμενη μέτρηση είναι αποθηκευμένη στο commit353ab8392f6b7af6e195a9e324de12159b6735e6. Το `total_changes()` μόνο του δεν μετρά όλο το κόστος.

Η αρχική αντιγραφή πραγματικών πληροφοριών εξακολουθεί να έχει κόστος. Δεν υπόσχεται κανείς μηδενικές εγγραφές, απεριόριστο δωρεάν Cloudflare ή κατάργηση ορίου με deploy. Αλλαγή batch size μόνη της δεν μειώνει το σύνολο.

## Συνεπές backup χωρίς πλήρεις SQL αντιγραφές

- Χρησιμοποιείται το ήδη υπάρχον ιδιωτικό R2 `SERVICE_DOCS`, με ξεχωριστό hashed namespace ανά realm/generation. Δεν ανοίγει νέο bucket, public access ή πλάνο.
- Οι τρέχοντες canonical πίνακες διαβάζονται σε typed σελίδες έως64γραμμών, με στόχο512KiB. Αποθηκεύονται με SHA-256 και immutable content-addressed keys. Αμετάβλητες σελίδες επαναχρησιμοποιούνται. Οι μεγάλοι πίνακες δεν αντιγράφονται σε προσωρινούς πίνακες Durable Objects.
- Ο Server2.11.1 προχωρά αυτόματα τις παρτίδες με protocol2. Κάθε cloud αίτημα προετοιμάζει έως8σελίδες/5δευτερόλεπτα, με μικρό durable pointer. Επανεκκίνηση ή χαμένο ACK συνεχίζει την ίδια εργασία. Το προηγούμενο πλήρες σημείο παραμένει διαθέσιμο μέχρι το επόμενο επιτυχές commit.
- **Οι σταδιακές αναγνώσεις δεν αρκούν ως απόδειξη συνέπειας.** Πριν δημοσιευτεί νέο σημείο, γίνεται πλήρης επανέλεγχος σχήματος, όλων των typed σελίδων και της αντιστοίχισης ιδιωτικών αρχείων μέσα σε ένα serialized CloudBusiness event fence. Αλλαγμένος πίνακας/χάρτης αρχείων επαναλαμβάνεται. Η σύντομη τελική σάρωση δεν κάνει R2 network I/O· έχει όριο15δευτερολέπτων και αποτυγχάνει με διατήρηση προηγούμενου σημείου αν δεν μπορεί να ολοκληρωθεί. Δεν εμφανίζεται μικτό ή παλιό snapshot ως νέο.
- Το SQLite sequence high watermark καταγράφεται στην ίδια τελική φραγή. Διατηρούνται rowid,64bit INTEGER, REAL, empty BLOB, NULL, Unicode και έως99στήλες. Το native format παραμένει schema1 και ανακατασκευάζεται στην πραγματική `CloudBackupDatabase`.
- Μετά το commit, ανάγνωση rows/files γίνεται μόνο από τις συγκεκριμένες immutable σελίδες/εκδόσεις R2. Ελέγχεται το SHA κάθε JSON σελίδας. Επόμενες αλλαγές της κύριας βάσης δεν αλλάζουν το backup.
- Το κινητό συνεχίζει κανονικά με ιδιωτική SQLite, πλήρη FCB3 κρυπτογράφηση και πραγματικό isolated restore. Δεν χρησιμοποιείται η αποσυρμένη τοπική SQLite ως υποκατάστατο της τρέχουσας cloud βάσης.
- Τα παλιά SQL backup points παραμένουν αναγνώσιμα· τα αρχικά canonical δεδομένα, ιδιωτικά αρχεία και τυχόν παλιές προσωρινές SQL clones δεν διαγράφονται. Αποτυχημένη προετοιμασία μπορεί να αφήσει μη δημοσιευμένες ιδιωτικές R2 σελίδες. Δεν εκτελείται αυτόματη συλλογή/διαγραφή τους σε αυτή την έκδοση.
- Παλιότερος εγκατεστημένος Server μπορεί να ολοκληρώσει μικρό σημείο με το υπάρχον `start`. Μεγάλο σημείο επιστρέφει ρητή εκκρεμότητα και συνεχίζει στην επόμενη προσπάθεια. Αν η παλιά pre-update backup ροή εμποδίζει την OTA, η εγκατάσταση του αρχικά υπογεγραμμένου Server APK2.11.1 από το GitHub επιτρέπει την αυτόματη συνέχεια· δεν αφαιρείται η απαίτηση backup ούτε επιστρέφεται ψευδής επιτυχία.

Το R2 έχει δικά του όρια αποθήκευσης/λειτουργιών. Η λύση μεταφέρει το αρχείο backup εκεί και αυξάνει τις αναγνώσεις/λειτουργίες R2, δεν εξαφανίζει το κόστος. Ισχύει η [επίσημη τιμολόγηση R2](https://developers.cloudflare.com/r2/pricing/), με μηνιαία δωρεάν ποσόστωση. Η [SQLite-DO τιμολόγηση](https://developers.cloudflare.com/durable-objects/platform/pricing/) έχει διαφορετικά ημερήσια όρια. Δεν έγινε αλλαγή billing/πλάνου ή υπόσχεση ότι η πραγματική χρήση του λογαριασμού είναι κάτω από αυτά. Για τον σχεδιασμό αιτημάτων λήφθηκε υπόψη το [30s όριο blockConcurrencyWhile](https://developers.cloudflare.com/durable-objects/api/state/).

## Ευρετήρια, υγεία και διανομή

- Το γενικό `cloud_store_source` παραμένει για γρήγορες αναγνώσεις scope/kind/day/store. Το JSON index αντικαθίσταται με το partial `cloud_cash_order_identity_v2`, μόνο για `kind='cash_snapshot_order'`. Το πραγματικό EXPLAIN QUERY PLAN εξακολουθεί να το επιλέγει στην αναζήτηση Ταμείου. Απλή νέα raw order χρειάζεται3SQL writes αντί4(PK+γενικό index, χωρίς άσχετο JSON index). Η αλλαγή αφαιρεί μόνο το παλιό index, καμία γραμμή δεδομένων.
- Η υγεία καταγράφει δημιουργία, αλλαγή severity, επίλυση και νέα εμφάνιση προειδοποίησης. Αμετάβλητη παρατήρηση διαβάζει μόνο. Το `observedAt` μένει ζωντανό και το `last_at` εμφανίζεται ως «τελευταία αλλαγή». Οι ατομικές acknowledgements, audit και οι κανόνες άγνωστης/παλιάς μέτρησης διατηρούνται.
- Ο συγχρονισμός εξακολουθεί να στέλνει μόνο πραγματικές αλλαγές και πλήρεις source coverage αποδείξεις. Δεν αφαιρέθηκαν οικονομικά audit, πηγή φρεσκάδας, αποδείξεις ακύρωσης ή επανεξέταση μετά από χειροκίνητη αλλαγή. Δεν τεκμηριώθηκε ότι αμετάβλητο cash snapshot ξαναγράφει όλες τις παραγγελίες· ο υπάρχων fast path διατηρείται.
- Οι ήδη ανεξάρτητες release/download διαδρομές εκτελούνται πριν από lookup της business authority. Κρατούν την αρχική αυθεντικοποίηση deploy/Server και το ξεχωριστό release metadata. Έτσι ένα quota error στη business DO δεν εμποδίζει τη διάθεση διορθωτικής ενημέρωσης. Business APIs συνεχίζουν να απαιτούν την πραγματική authority, χωρίς επιστροφή στην παλιά D1 ή άρση fence.


- Η αυθεντικοποίηση cloud εξακολουθεί να ελέγχει την τρέχουσα συνεδρία/λήξη/ενεργό χρήστη/δικαιώματα σε κάθε αίτημα. Μόνο τα επαναλαμβανόμενα timestamps τελευταίας παρουσίας session/user/device συγχωνεύονται ανά5λεπτο αντί ανάλεπτο, έως80% λιγότερες περιοδικές ενημερώσεις σε σταθερή χρήση. Η ανάκληση λογαριασμού παραμένει άμεση, χωρίς auth cache. Native/D1 κρατούν το προηγούμενο διάστημα. Real Workerd regression:30authenticated reads μετά το πρώτο λεπτό χωρίς touch, touch μετά5λεπτά και άμεσο401μετά ανάκληση.

## Έλεγχοι και παραγωγικά όρια

`test-cloud-backup.mjs`: πραγματικό SQLite-DO/R2, μηδενικά SQL writes κατά το backup, durable resume/χαμένο ACK, αλλαγή ήδη αποθηκευμένης σελίδας/διαγραφή/χάρτη ιδιωτικού αρχείου μεταξύ παρτίδων, επανέλεγχος πριν το commit, immutable rows/files,99στήλες/τύποι/sequence, κλειστή πρόσβαση και αλλοίωση R2, legacy reads, partial index query plan,30health reads χωρίς writes και κανονική επίλυση/επανεμφάνιση.

`test-cloud-return.mjs`: ολόκληρη υπογεγραμμένη επιστροφή και ανάκτηση, πραγματική cloud αυθεντικοποίηση/Ταμείο/αναφορές χωρίς Android socket, μεγάλα Unicode/99στήλες/ιδιωτικά αρχεία και unchanged D1. `test-business-runtime-native.mjs`: πραγματικός Android importer/exporter, πλήρης FCB3/decrypt/isolated restore. Ακολουθεί το υποχρεωτικό πλήρες exact-source CI πριν κανονική δημοσίευση.

Η κατάσταση της παραγωγικής μεταφοράς και το αν ο ιδιοκτήτης ολοκλήρωσε την επιστροφή **δεν αποδεικνύονται από τα συνθετικά tests**. Για επιστροφή παραμένει ο υπάρχων φυσικός έλεγχος στον Server → Ρυθμίσεις → Κύρια βάση δεδομένων → Επιστροφή/Συνέχεια επιστροφής. Δεν έγινε παραγωγικό backup/restore/delete από τον agent.
