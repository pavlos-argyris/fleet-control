# Issue #95 — κανονικό Server με πρόσθετο Direct backend

Κατάσταση: υποψήφια υλοποίηση στο `codex/issue-95-unified-server-mode`, από main ea38d7d και απομονωμένο #91/1de75ef. Δεν έχει δημοσιευτεί ούτε ενεργοποιηθεί σε παραγωγή. Οι δοκιμές, η υπογραφή και η πραγματική συσκευή καταγράφονται χωριστά στο handoff.

## Επιλογή και δεδομένα

Αρχικό default Cloudflare: `https://fleet-control.pavlosargyris.workers.dev`. Direct: `https://fleet-control.duckdns.org`. Ο μοχλός στις υπάρχουσες Ρυθμίσεις Server δεν κάνει cloud API, migration, διαγραφή, αντιγραφή ή συμφιλίωση. Username/password ιδιοκτήτη επαληθεύονται στην εισαχθείσα τοπική βάση, με πραγματικό ρόλο owner. Μη έτοιμο Direct αποθηκεύει μόνο ζητούμενη προετοιμασία, με ενεργό το προηγούμενο backend και σαφή αιτία. Offline Direct μετά ενεργοποίηση διατηρεί την επιλογή. Επιστροφή Cloudflare είναι τοπική επιλογή, όχι υπόσχεση διαθεσιμότητας Cloudflare.

Το `BackendMode` φυλάσσει schema/revision/selectedMode/activeMode σε atomic αρχείο με fsync. CAS αποτρέπει διπλές/παλιές εντολές. Shared OS file locks κρατούν τις εργασίες σε εξέλιξη μέχρι ολοκλήρωση· αποκλειστικό lock εφαρμόζει αλλαγή και μεταξύ processes. Κατεστραμμένη επιλογή μπλοκάρει cloud writes. Κάθε κανονικό FleetHttp operation κρατά lease μέχρι κατανάλωση απάντησης. Το Direct API ελέγχει active mode και revision πριν επιχειρησιακή εργασία, χωρίς επανάληψη χρηματικής εντολής σε άλλο backend.

Το ίδιο κανονικό package/signature διατηρεί MainActivity, tabs και Cloudflare SQLite. Τα γνωστά Independent backend/auth/restore/TLS υλικά παράγονται αναπαραγώγιμα σε namespace `gr.argyrismitsos.fleetdirect` και process `:direct`, με ξεχωριστά `app_fleet_direct` αρχεία/SQLite, pref prefixes, Keystore aliases και statics. Το κανονικό SQLite provider δεν αντικαθίσταται. Η Direct πλευρά χρησιμοποιεί pinned επίσημη SQLite με JSON/WAL/FULL και τους ελέγχους πλήρους FCB3. Δεν εισάγει αυτόματα το backup άλλης εφαρμογής. Ιδιωτικό same-UID ContentProvider/Activity/Service δεν εξάγει admin endpoint στο δίκτυο. Στατιστικά Direct προέρχονται από τη δική της βάση.

## Κανονικά native εργαλεία ανά λειτουργία

Η ίδια MainActivity και τα ίδια assets με τις τέσσερις καρτέλες μεταγλωττίζονται και για το :direct. Ο launcher και η επιστροφή από background ανοίγουν το UI του αποθηκευμένου mode, χωρίς εναλλαγή στη μέση μίας φόρμας. ScopedContext απομονώνει ρυθμίσεις, SAF folder/ledger, φορητό κωδικό, Ordexa credentials, backup προόδους και installer state. Σε Android28+ το :direct WebView έχει δικό του data-directory suffix. Το Cloudflare UI διατηρείται ακέραιο. Η παλιά μεταφορά/σύζευξη αφορά μόνο Cloudflare· στο Direct εμφανίζεται σύνδεση με username/password και χρησιμοποιείται ο ενιαίος μοχλός.

Τα χειροκίνητα και προγραμματισμένα Direct backup χρησιμοποιούν τα κανονικά BackupJobs: πλήρες encrypted FCB3 (.fcbackup/.fcdb/.fcdocs), συνεπές SQLite snapshot, immutable αρχεία, πραγματική απομονωμένη ανάκτηση και SAF read-back. Το ledger/retention είναι χωριστά και δεν καθαρίζουν ξένα Cloudflare/source backup. Η πλήρης ανάκτηση έχει προεπισκόπηση/λογαριασμούς/επιβεβαίωση αντικατάστασης, πριν-backup, διατήρηση προηγούμενων καταλόγων, cold journal/fsync, νέα generation/συνεδρίες και νέο ελεγμένο backup πριν ανοίξουν οι εγγραφές. Δεν περιέχει Cloudflare reservation/API.

Η καρτέλα Ενημερώσεις διατηρεί τοπικό immutable Direct κατάλογο Client/Web/Server. Το ανέβασμα Client ελέγχει την αρχική υπογραφή του ενσωματωμένου Client. Τα Web πακέτα δεν μπορούν να αντικαταστήσουν τα προστατευμένα modules επιλογής λειτουργίας/ίδιας προέλευσης. Υποστηρίζεται επαναφορά σε προηγούμενο ή ενσωματωμένο Client/Web. Τα native εργαλεία Ordexa και οι background readers χρησιμοποιούν αποκλειστικά το scope και τα credentials της επιλεγμένης λειτουργίας.

## Διανομή και πραγματικοί περιορισμοί

Ο HTTPS Direct listener διαθέτει μόνο ένα δημόσιο CORS discovery document `/fleet-mode.json`, χωρίς credentials/δεδομένα· τα business APIs παραμένουν same-origin, authenticated και role-checked. Client/Web ελέγχουν αυτό το σταθερό endpoint ανά 15s όταν είναι ορατά. Η Cloudflare CSP επιτρέπει μόνο αυτόν τον πρόσθετο HTTPS origin. Προϋπόθεση λήψης νέας εντολής είναι να φτάνει το δίκτυο στον Direct Server. Δεν υπάρχει καθολική στιγμιαία αλλαγή όταν Direct και Cloudflare είναι εκτός σύνδεσης.

Το Direct Web κρατά service-worker cache μόνο για το στατικό περιβάλλον/κουμπί ανάκτησης, μετά το πρώτο επιτυχές φόρτωμα. Offline reload λειτουργεί χωρίς επιτυχή κλήση Cloudflare ή Direct API. API, mode descriptor και APK δεν αποθηκεύονται στην cache και καμία αποτυχημένη οικονομική POST δεν επαναλαμβάνεται στην επανασύνδεση. Μία συσκευή/browser που δεν έχει ποτέ φορτώσει το περιβάλλον χρειάζεται αρχική πρόσβαση ή το bundled Android Client.

Κάθε Client και κάθε browser origin κρατά last-known mode/revision. Η αλλαγή ακυρώνει προηγούμενα fetches/polling, απορρίπτει παλιές απαντήσεις και φορτώνει άλλο origin, με χωριστές browser sessions/caches. Native tokens έχουν ξεχωριστά Keystore AES-GCM κλειδιά και AAD ανά backend, με ατομική μετατροπή παλιών remembered tokens. Η Java bridge συνδέει το token με το origin της φορτωμένης σελίδας, όχι με μία μεταβατική αλλαγή επιλογής πριν από navigation. Native ειδοποιήσεις και ZIP τιμολογίων κρατούν captured realm/revision και δεν επαναλαμβάνουν αίτημα σε άλλο backend. Οι χρήστες συνδέονται ξανά με username/password της συγκεκριμένης βάσης. Τοπική «Ανάκτηση Cloudflare» λειτουργεί χωρίς endpoint, δεν αλλάζει τον ενιαίο Server διακόπτη, και δεν αναιρείται από παλιό discovery. «Λήψη επιλογής Server» επαναφέρει τη διανομή.

Νέος browser που δεν έχει ήδη φορτωμένη/αποθηκευμένη εφαρμογή δεν μπορεί να λάβει JavaScript από μη διαθέσιμο Cloudflare. Ανοίγει το γνωστό Direct URL. Ήδη ανοικτές καρτέλες και Android bundled shell μπορούν να κάνουν ανεξάρτητο discovery. Η native εφαρμογή δείχνει ανάκτηση/επανάληψη ακόμη όταν το Direct document δεν φορτώνει. Cross-origin storage δεν μοιράζεται· δεν προσποιείται αλλαγή όλων των offline καρτελών.

## HTTPS και router

Χρησιμοποιείται ACME **DNS-01**, όχι HTTP-01. Η έκδοση/ανανέωση πιστοποιητικού δεν χρειάζεται inbound80. Κώδικας: `IndependentAcme` επιλέγει dns-01 και περιμένει μη κενό matching TXT. Επίσημη τεκμηρίωση: https://letsencrypt.org/docs/challenge-types/ . Δεν εκτίθεται ανασφαλής HTTP υπηρεσία.

Η αλυσίδα PEM διαβάζεται ανά πιστοποιητικό (διόρθωση #94/ace4a71), με SAN, validity, trust και keypair proof. Το `CERT_CHAIN_CHAIN` δεν αποδίδεται σε κλειστό router port. Υπάρχουν ασφαλείς επιμέρους κωδικοί χωρίς secrets. Ο listener δεσμεύει **8443** και εκθέτει πραγματική bound κατάσταση/διεύθυνση/θύρα, όχι υπόθεση443. DNS update, CA/TXT, TLS και inbound reachability εμφανίζονται χωριστά.

Ο ιδιοκτήτης, μετά έγκυρο TLS/listener, κρατά σταθερή DHCP διεύθυνση κινητού και ορίζει TCP **εξωτερική443 → IPκινητού:8443**. Δεν απαιτείται κανόνας80→8080. Ελέγχει ότι Nova WAN/public IP συμφωνούν και δοκιμάζει από διαφορετικό 4G/5G στο σωστό hostname. Αποτυχία LAN hostname με επιτυχή WAN πιθανόν χρειάζεται NAT loopback/split DNS· δεν παρακάμπτεται TLS με πρόσβαση IP/trust-all.

Αν τρέχει ήδη στο ίδιο κινητό η παλιά ξεχωριστή δοκιμαστική εφαρμογή Independent Server, σταμάτησε τη δοκιμαστική υπηρεσία πριν ξεκινήσεις τον νέο Direct listener στην8443. Δεν απαιτείται απεγκατάσταση ή διαγραφή δεδομένων. Η κατάσταση listener δείχνει τυχόν αποτυχία δέσμευσης της θύρας.

Πρώτη προετοιμασία από browser: `https://fleet-control.duckdns.org/?fleetSetup=1`, login owner → Έλεγχος σύνδεσης σε δεδομένα κινητής. Επιχειρησιακά Direct writes παραμένουν μπλοκαρισμένα όσο activeMode είναι Cloudflare. Ο Server μοχλός επιτρέπει Direct μόνο με verified full backup, owner auth, έγκυρο TLS, πρόσφατη κατάσταση listener και πρόσφατο πραγματικό public-peer read/write-rollback probe. Δεν έγινε τέτοια φυσική δοκιμή από agent.

## Ενημερώσεις, backups και gates

### Πρώτη ενεργοποίηση από τον ιδιοκτήτη

1. Εγκατέστησε το κανονικό Server APK με την αρχική υπογραφή, πάνω από την υπάρχουσα εφαρμογή **χωρίς απεγκατάσταση**. Η αρχική επιλογή παραμένει Cloudflare. Αν ο παλιός updater απορρίπτει το μέγεθος, χρησιμοποίησε το υπογεγραμμένο APK της ίδιας έκδοσης από το GitHub Release.
2. Άνοιξε **Ρυθμίσεις → Cloudflare / Direct Android Server → Προετοιμασία Direct / backup / HTTPS**. Συμπλήρωσε τον φορητό κωδικό και επίλεξε τον φάκελο με τα τμήματα του ίδιου πλήρους backup: `.fcbackup`, `.fcdb` και, όταν περιέχει αρχεία, `.fcdocs`. Η εισαγωγή επιλέγει το `.fcbackup`· ένα μεμονωμένο `.fcdocs` δεν αρκεί. Μετά την επιτυχή επαλήθευση, κάνε «Έλεγχο σύνδεσης» με τον λογαριασμό ιδιοκτήτη από το backup.
3. Για το σταθερό `fleet-control.duckdns.org`, συμπλήρωσε το δικό σου DuckDNS token, αποδέξου τους όρους πιστοποιητικού και πάτησε **Ρύθμιση HTTPS και έναρξη Server**. Περίμενε έγκυρο πιστοποιητικό και ενεργό listener8443. DNS update από μόνο του δεν αποδεικνύει έτοιμο HTTPS.
4. Στο router κράτησε σταθερή τη διεύθυνση Wi-Fi που δείχνει ο Server και βάλε έναν κανόνα **WAN TCP443 → αυτή η IP:8443**. Η παλιά αναφορά192.168.1.193 χρειάζεται επανέλεγχο στη σημερινή συσκευή. Αν η WAN IP δεν συμφωνεί με τη δημόσια IPv4, απαιτείται διερεύνηση CGNAT. Μην αντικαταστήσεις το hostname με IP για να παρακάμψεις το πιστοποιητικό.
5. Σε δεύτερο κινητό με Wi-Fi κλειστό, άνοιξε `https://fleet-control.duckdns.org/?fleetSetup=1`, συνδέσου ως ιδιοκτήτης και πάτησε **Έλεγχος σύνδεσης**. Χρειάζεται επιτυχής πραγματικός εξωτερικός read/write-rollback έλεγχος. Η άδεια του μοχλού χρησιμοποιεί πρόσφατη απόδειξη δέκα λεπτών· αν παρέλθει, επανάλαβε τον έλεγχο.
6. Επέστρεψε στις κανονικές **Ρυθμίσεις Server**, συμπλήρωσε τα στοιχεία ιδιοκτήτη στη νέα φόρμα και άλλαξε τον μοχλό σε **Direct Android Server**. Έλεγξε την ένδειξη **Ενεργό** και τυχόν αιτία προετοιμασίας. Δεν υπάρχει δεύτερο modal. Η αποτυχία δεν δηλώνεται ως επιτυχής σύνδεση.
7. Οι Clients λαμβάνουν την επιλογή όταν φτάσουν στον Direct Server και συνδέονται με λογαριασμό της βάσης Direct. Ρύθμισε Ordexa και ξεχωριστό φάκελο νέων backup μέσα στο Direct UI. Έλεγξε Wi-Fi και 4G, μία συνήθη αλλαγή/ανάγνωση, backup με επαλήθευση και επανεκκίνηση. Σε διακοπή η επιλογή παραμένει Direct· η χειροκίνητη επιστροφή σε Cloudflare αλλάζει μόνο τη λειτουργία και δεν συγχρονίζει δεδομένα.

Αν επέστρεψες χειροκίνητα σε Cloudflare με εκκρεμή ανάκτηση Direct, άνοιξε ξανά **Προετοιμασία Direct / backup / HTTPS**. Με σύνδεση ιδιοκτήτη εμφανίζεται η έτοιμη επανεκκίνηση ή η ολοκλήρωση με νέο ελεγμένο backup, ανάλογα με το στάδιο. Εκκρεμής ενημέρωση που δεν έχει φτάσει στον Android installer μπορεί επίσης να αναβληθεί από εκεί. Αυτές είναι χωριστές χειροκίνητες ενέργειες· ο μοχλός δεν εκτελεί ανάκτηση, συγχρονισμό ή αλλαγή δεδομένων.

Κανονική έκδοση υποψηφίου: Client5.63.0/code107, Server2.12.0/code77, Web5.63.0, Worker5.20.0. Αρχικά signing keys μόνο στο εγκεκριμένο CI. Τοπικές υπογραφές είναι disposable και δεν παραδίδονται ως εγκαταστάσιμη ενημέρωση. Τα παλιά immutable Web snapshots διατηρούνται.

Η συνεχής ιδιωτική HTTPS υπηρεσία Direct δηλώνει `FOREGROUND_SERVICE_SPECIAL_USE` για τον τύπο foreground service που απαιτεί το Android34+. Η compiled δήλωση περιορίζεται στην μη εξαγόμενη `IndependentService`, στο `:direct`, με συγκεκριμένο περιγραφικό subtype. Ο έλεγχος ιστορικών APK δέχεται μόνο αυτή τη συγκεκριμένη προσθήκη και διατηρεί τους ελέγχους κάθε άλλου permission, exported component, package και υπογραφής. Δεν προσθέτει δικαιώματα προσωπικών δεδομένων. Επίσημη αναφορά: https://developer.android.com/develop/background-work/services/fgs/service-types#special-use .

Direct Client ενημερώσεις διαβάζουν δημόσιο GitHub release manifest, με allowlisted HTTPS redirects χωρίς Fleet/Ordexa credentials, digest/μέγεθος και υπάρχον έλεγχο Android υπογραφής/package. Νεότερη ρητή οδηγία ιδιοκτήτη: επιτρέπεται APK πάνω από50MB, με προτεραιότητα σε όλες τις λειτουργίες. Ο Server περιλαμβάνει ολόκληρο το υπογεγραμμένο Client byte προς byte και όλα τα SQLite ABI. Τα νέα Android download/installer/audit και publishing όρια γίνονται192MiB. Μεγάλα APK ανεβαίνουν σε R2 με bounded FixedLengthStream και SHA-256 verification. Η πρώτη εγκατάσταση πάνω σε παλιό updater50MiB μπορεί να γίνει χειροκίνητα από το αρχικό signed GitHub APK, με ίδιο package/κλειδί και χωρίς απεγκατάσταση. Δεν παρουσιάζεται ως ήδη συμβατή αυτόματη λήψη από παλιό updater που δεν γνωρίζει το νέο όριο. Ο Direct Server ελέγχει ανά ώρα το δημόσιο GitHub κανάλι, κατεβάζει το APK χωρίς Fleet/Ordexa credentials και χρησιμοποιεί την κανονική αυτόματη OTA διαδικασία: παύση νέων εργασιών, πλήρες φορητό Direct backup με πραγματική δοκιμή ανάκτησης, επαλήθευση αρχικής υπογραφής/πακέτου/hash και Android installer. Η callback κατάσταση εγκατάστασης παραμένει στο ίδιο :direct process και pref scope. Η cloud automatic OTA δεν χρησιμοποιείται ως εναλλακτική Direct checkpoint.

Merge/publish απαιτούν πλήρες exact-source CI, compiled APKs/αρχικές υπογραφές/μεγέθη, instrumentation και screenshots. Πραγματικά backup ιδιοκτήτη/κινητό/Nova4G/reboot/θερμική δοκιμή είναι διαφορετικά acceptance checkpoints και δεν αντικαθίστανται με fixtures. Δεν γίνεται ενεργοποίηση Direct από agent, Cloudflare disable, έξοδο ή παραγωγικό restore/delete.
