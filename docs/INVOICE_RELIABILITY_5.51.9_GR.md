# Αξιοπιστία τιμολογίων — 5.51.9, Issues #1 και #3

Client/Web 5.51.9, Client versionCode 81, Worker 5.12.9. Ο Server παραμένει συμβατός στην 2.2.15 / code 41. Περιλαμβάνεται η ανεξάρτητα ελεγμένη αλλαγή landscape του PR #15, με νέα τελική έκδοση Client και διατήρηση των κοινών ελέγχων/καταγραφών.

## Αιτίες που αναπαράχθηκαν

- Το άνοιγμα τιμολογίου έστελνε «διαβάστηκε», που άλλαζε το updatedAt του service. Η ίδια φόρμα απορριπτόταν έπειτα με 409 «Το service άλλαξε».
- Η επιβεβαίωση αποθήκευε πρώτα το snapshot και μετά, χωριστά, την ουρά Server και το audit. Ελεγχόμενη αποτυχία της ουράς επέστρεφε 500 ενώ η επιβεβαίωση είχε ήδη αποθηκευτεί.
- Κοινό version guard και πλήρης κλωνοποίηση/κανονικοποίηση στόλου προκαλούσαν άσχετες συγκρούσεις και περιττή εργασία.
- Η λίστα επέστρεφε πλήρες raw OCR/evidence και ιστορικό αποφάσεων για όλα τα τιμολόγια. Τα παρεχόμενα production logs δείχνουν exceededCpu/503· δεν έχουμε νέο production CPU profile για να εξισώσουμε κάθε 503 με μία συγκεκριμένη γραμμή.
- Αποτυχημένη νέα ανάγνωση μπορούσε να ξαναγράψει εργασίες/χειρόγραφη σημείωση/συνεργείο του service. Καθυστερημένη απάντηση λίστας μπορούσε να επαναφέρει παλιά κατάσταση στην οθόνη.

## Τι αλλάζει

- Εγγραφή απόδειξης επανάληψης, επιλεγμένων entries, μητρώου, ουράς και audit σε μία ατομική D1 batch transaction. Αποτυχία αναιρεί ολόκληρη τη συναλλαγή. Χρησιμοποιείται ο υπάρχων πίνακας idempotency_keys, χωρίς migration σχήματος.
- Κάθε αποστολή φόρμας έχει request ID ανά χρήστη. Ίδιες διορθώσεις μετά από χαμένη απάντηση επαναχρησιμοποιούν την προηγούμενη επιτυχία. Διαφορετικό περιεχόμενο με ίδιο ID απορρίπτεται. Το κανονικό επιβεβαιωμένο no-op δεν αλλάζει snapshot/version/journal/outbox/audit, μόνο αποθηκεύει τη μικρή απόδειξη αιτήματος.
- Σύγκριση πραγματικών στοιχείων service/τιμολογίου αντί ευμετάβλητης προόδου/seen. Ταυτόχρονη πραγματική αλλαγή προστατεύεται με 409, χωρίς αντικατάσταση νεότερων δεδομένων. Τα guards αφορούν τις επιλεγμένες εγγραφές και, όταν επανυπολογίζονται μετρητές, το συγκεκριμένο μηχανάκι.
- Η λίστα διατηρεί όλα τα τιμολόγια αλλά παραλείπει βαρύ OCR και journals. Τα πλήρη στοιχεία και το revision φορτώνονται στο ήδη υπάρχον transfer-options endpoint, με includeDocument=1, κατά το άνοιγμα. Το νέο compactResponse αποφεύγει πλήρες bike round trip. Οι παλιοί callers διατηρούν bike και πλήρες document στην απόκριση επιβεβαίωσης.
- Οι αντικαταστάσεις μηχανής προς Server ταξινομούνται κατά τον χρόνο συναλλαγής D1 και rowid για ισοπαλίες, ώστε δύο reviews με αντίστροφη σειρά ολοκλήρωσης να μη μεταφέρουν τελευταίο ένα παλιότερο snapshot. Το bike.updatedAt διατηρείται μη φθίνον.
- Η ένδειξη διαβάστηκε δεν αλλάζει την επιχειρησιακή σήμανση του service και επαναλαμβανόμενο seen είναι no-op. Σε αποτυχία OCR διατηρούνται τα χειροκίνητα στοιχεία/μετρητές/σημειώσεις και καταγράφεται αναγνώσιμο σφάλμα στο παραστατικό.
- Η UI διατηρεί διορθώσεις και εμφανίζει αποτυχία. Προχωρά στο επόμενο μόνο μετά επιβεβαιωμένη αποθήκευση χωρίς εκκρεμότητες. Αποκλείει παλιές απαντήσεις λίστας και αποτελέσματα προηγούμενης σύνδεσης. Δεν αλλάζει η συχνότητα polling ή ο ωριαίος έλεγχος OTA.
- Το Client ακολουθεί την περιστροφή της συσκευής, με ίδιο WebView και διατήρηση ανοιχτής φόρμας. Η τεκμηρίωση #3 ξεχωρίζει browser/file δοκιμές από φυσικό Android.

## Πραγματικές δοκιμές

Νέες δοκιμές actual Worker/SQLite και Workerd/D1 καλύπτουν σφάλμα μέσα στην ουρά μετά την εγγραφή snapshot, ολικό rollback μητρώου/receipt/audit/outbox, ασφαλή επανάληψη χαμένης απάντησης, no-op, διαφορετικό περιεχόμενο με ίδιο ID, αλλαγή άσχετου service, πρόοδο στο ίδιο service, πραγματική σύγκρουση, μεταφορά εντός/μεταξύ μηχανών, διαγραφή κατά την αποθήκευση και αποτυχημένο AI χωρίς μεταβολή service. Οι δοκιμές UI καλύπτουν διατήρηση φόρμας, request ID, αυτόματο επόμενο, παλιές αποκρίσεις και απομόνωση σύνδεσης.

Σε συνθετικό στόλο 40 μηχανών / 20.000 εγγραφών / 200 τιμολογίων, το payload λίστας μειώθηκε από 2.020.672 σε 191.434 bytes (περίπου 90,5%), με όλα τα τιμολόγια παρόντα. Δεν γίνεται parse ολόκληρου του στόλου στη JavaScript της λίστας. Οι τοπικοί χρόνοι SQLite δεν αποτελούν μέτρηση του CPU limit του Cloudflare Free ούτε εγγύηση μηδενικών 503 για αυθαίρετο όγκο.

Τα scripts/check-all.sh, το CI ακριβούς PR/main, οι υπάρχουσες browser/native δοκιμές, η κατασκευή δύο APK και ο Worker dry-run είναι οι τελικοί έλεγχοι. Η πραγματική κατάστασή τους και η δημοσίευση καταγράφονται στο PR #14 και στο CHATGPT_HANDOFF_GR.md. Δεν χαρακτηρίζεται ολοκληρωμένη η δημοσίευση από το παρόν source αρχείο.

## Εγκατάσταση, δεδομένα και επαναφορά

Η ενημέρωση Client εγκαθίσταται πάνω από την υπάρχουσα εφαρμογή με το αρχικό πιστοποιητικό. Web/Worker ενεργοποιούνται από την κοινή διαδικασία δημοσίευσης. Δεν απαιτείται απεγκατάσταση Server ή αλλαγή δεδομένων. Ολόκληρος ο πηγαίος κώδικας όλων των τμημάτων, APK/Web/Worker, build inputs, οδηγίες, manifest και SHA-256 παραδίδονται στο ιδιωτικό GitHub release.

Δεν έγινε δοκιμαστική μεταβολή παραγωγικών δεδομένων, μαζική ανάγνωση πραγματικών τιμολογίων, εγκατάσταση σε φυσική συσκευή ή νέο παραγωγικό backup. Για αποκατάσταση κώδικα ακολουθείται η υπάρχουσα διαδικασία με νέο αυξημένο versionCode και συμβατά δεδομένα· δεν διαγράφονται receipts/ιστορικό ούτε υπόσχεται η αλλαγή ασφαλές παλιό Android downgrade.

Μετά τη δημοσίευση ελέγχονται read-only οι ενεργές εκδόσεις, τα APK/Web hashes και η απόκριση υπηρεσίας. Ο χρήστης επιβεβαιώνει στη συσκευή επιβεβαίωση τιμολογίου/landscape. Αν εμφανιστεί 503, διατηρούνται οι διορθώσεις και συλλέγεται το endpoint/ώρα/ray/outcome από logs για περαιτέρω μέτρηση, χωρίς αυτόματη μαζική επανάληψη AI.
