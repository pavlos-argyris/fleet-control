# Fleet Control 5.36.6 — Ενημέρωση και επαναφορά

Ημερομηνία ελέγχου: 09/10/2026. Οδηγός για τον υπάρχοντα Server 2.0.11 και Worker 5.0.40 του πακέτου 5.36.5. Δεν έγινε σύνδεση με τον παραγωγικό σου λογαριασμό, deploy ή λήψη πραγματικών δεδομένων.

## Περιεχόμενο και συμβατότητα

| Τμήμα | Έκδοση μετά την ενημέρωση | Αρχείο/φάκελος |
|---|---|---|
| Server APK | 2.0.12, versionCode 15 | `dist/Fleet_Control_Server_v2.0.12.apk` |
| Client APK | 5.36.5, versionCode 46 | `dist/Fleet_Control_Client_v5.36.5.apk` |
| Worker | 5.0.41 | `cloudflare-worker/src/` |
| Web/Portal | Αρχεία του πακέτου 5.36.6, frontend 5.36.5 | `cloudflare-worker/public/` |
| Πλήρες ανεξάρτητο έργο | Όλα τα παραπάνω | `source/Fleet_Control_Developer_Project_v5.36.6.zip` |

Η νέα λειτουργία αφορά παράλληλη επεξεργασία τιμολογίων 1–10, με προεπιλογή 4. Ο Client και τα web assets διατηρούν την 5.36.5. Αν έχεις ήδη Client 5.36.5, δεν απαιτείται νέα εγκατάστασή του γι' αυτή την αλλαγή.

Η σύγκριση Worker 5.0.40 → 5.0.41 έδειξε μόνο αλλαγή runtime version και επέκταση της απάντησης της ουράς με παράθυρο πολλών τιμολογίων. Οι ορισμοί SQL και ο κώδικας workforce παραμένουν ίδιοι. Δεν απαιτείται εκτέλεση νέου χειροκίνητου SQL migration γι' αυτή τη μετάβαση. Αυτό αφορά αυτά τα δύο πακέτα, όχι κάποια διαφορετική εγκατεστημένη έκδοση.

## 1. Πρώτα αντίγραφα ασφαλείας

Κάνε τη διαδικασία σε ήσυχο διάστημα χωρίς νέες καταχωρήσεις, Clock In/Out ή μαζική επεξεργασία. Άφησε τον υπάρχοντα Server να ολοκληρώσει τον συγχρονισμό και την τοπική λήψη PDF. Σημείωσε αριθμό μηχανών, εργαζομένων, βαρδιών και τιμολογίων και την ώρα του τελευταίου επιτυχούς συγχρονισμού.

### A. Από τον Server

Άνοιξε **Backup → Δημιουργία backup τώρα**. Χρειάζεται επιλεγμένος φάκελος με δικαίωμα εγγραφής. Κράτησε στον υπολογιστή αντίγραφα με την ίδια ημερομηνία/ώρα:

- `FleetControl_backup_YYYYMMDD_HHMMSS.fcbackup`: στόλος/ιστορικό και το τελευταίο τοπικά συγχρονισμένο αντίγραφο των 27 πινάκων προσωπικού, προγράμματος, μισθοδοσίας κ.ά., μαζί με ορισμένες ρυθμίσεις Server.
- `FleetControl_documents_YYYYMMDD_HHMMSS.fcdocs`: τα συνημμένα που υπάρχουν πραγματικά στην τοπική αποθήκη του Server.

Μην αλλάξεις τα ονόματα και κράτησε τα δύο αρχεία στον ίδιο επιλεγμένο φάκελο. Η εφαρμογή βρίσκει το συνοδευτικό αρχείο από το κοινό timestamp.

Το μήνυμα «Επιτυχία» μόνο του δεν αποδεικνύει ότι αποθηκεύτηκαν όλα τα PDF. Ο κώδικας παραλείπει συνημμένα που δεν υπάρχουν τοπικά. Αν δεν υπάρχει τοπικό πλήρες αντίγραφο, η πληρότητα των τιμολογίων στηρίζεται και στο R2 backup.

### B. Πλήρες SQL αντίγραφο D1 και σημείο επαναφοράς

Από τον παλιό, σωστά ρυθμισμένο φάκελο `cloudflare-worker` σε PowerShell, με πρόσβαση στον δικό σου λογαριασμό:

```powershell
New-Item -ItemType Directory -Force ..\backups-before-5.36.6
Copy-Item .\wrangler.jsonc ..\backups-before-5.36.6\wrangler.before.jsonc
npx wrangler whoami
npx wrangler d1 list
npx wrangler d1 export fleet-control-db --remote --output=../backups-before-5.36.6/fleet-before-update.sql
npx wrangler d1 time-travel info fleet-control-db
npx wrangler deployments list
```

Αν το πραγματικό `database_name` διαφέρει, άλλαξε το `fleet-control-db`. Έλεγξε ότι το `.sql` δημιουργήθηκε, έχει περιεχόμενο και η εντολή ολοκληρώθηκε επιτυχώς. Φύλαξε την έξοδο Time Travel και το ID της ενεργής έκδοσης Worker. Μην επαναχρησιμοποιείς το ίδιο όνομα SQL σε επόμενες ενημερώσεις χωρίς να κρατήσεις το προηγούμενο αντίγραφο.

Το Time Travel της D1 επιτρέπει επιστροφή σε bookmark/χρονική στιγμή μέσα στο διαθέσιμο παράθυρο: 7 ημέρες στο Free ή 30 στο Paid. Το ανεξάρτητο SQL αντίγραφο παραμένει χρήσιμο μετά τη λήξη αυτού του παραθύρου. Έλεγξε το πραγματικό πλάνο/διαθέσιμο bookmark στον λογαριασμό σου.

### C. Αντίγραφο R2 για τα ίδια τα PDF

Η SQL βάση κρατά εγγραφές και αναφορές αρχείων. Τα bytes των PDF βρίσκονται χωριστά στο R2 και χρειάζονται δικό τους αντίγραφο.

Έλεγξε τα πραγματικά bucket names στο ενεργό `wrangler.jsonc`. Το πακέτο δηλώνει `SERVICE_DOCS` και `RELEASES`. Παλαιότερη εγκατάσταση μπορεί να έχει τιμολόγια και στο bucket `RELEASES`, οπότε κράτησε και τα δύο.

Με rclone ρυθμισμένο για τον δικό σου R2 λογαριασμό και remote με όνομα `r2`:

```powershell
rclone copy r2:fleet-control-service-documents ..\backups-before-5.36.6\r2-documents --progress
rclone copy r2:fleet-control-releases ..\backups-before-5.36.6\r2-releases --progress
```

Οι εντολές αντιγράφουν από cloud σε υπολογιστή. Αν τα ονόματα διαφέρουν, χρησιμοποίησε τα δικά σου. Η αρχική ρύθμιση απαιτεί R2 Access Key, Secret Access Key και endpoint· ακολούθησε την επίσημη πηγή στο τέλος. Έλεγξε ότι δεν υπήρξαν σφάλματα και άνοιξε δείγματα PDF από το αντίγραφο.

### D. Πρόσβαση και ρυθμίσεις

Κράτησε ιδιωτικά το ενεργό `wrangler.jsonc`, Worker name/URL, Cloudflare account, D1 ID, ονόματα buckets, τα υπάρχοντα `CLIENT_KEY`, `SERVER_KEY`, `PIN_PEPPER` και όποια άλλα secrets χρησιμοποιεί η εγκατάστασή σου. Ο οδηγός δεν ανακτά τα μη ορατά secrets του λογαριασμού σου. Μην τα αλλάξεις κατά το update. Κράτησε και το τρέχον Admin PIN που απαιτεί η επαναφορά μέσα από τον Server.

## 2. Ενημέρωση Web/Worker από Windows

Χρειάζεται Node.js 22 ή νεότερο για το Wrangler 4.148.0 που χρησιμοποιήθηκε στο έργο. Για επανάληψη όλων των δοκιμών του έργου χρησιμοποιήθηκε Node.js 24.19.0.

1. Αποσυμπίεσε ολόκληρο το νέο πακέτο σε νέο φάκελο. Κράτησε τον παλιό φάκελο ακέραιο.
2. Αντέγραψε το **δικό σου ενεργό** `wrangler.jsonc` στη θέση του αντίστοιχου αρχείου στον νέο `cloudflare-worker/`. Έλεγξε ίδιο Worker name, σωστό D1 ID, ίδια R2 buckets, `ASSETS` με `./public` και τυχόν AI binding. Το περιεχόμενο config του αρχείου παράδοσης δεν αποδεικνύει τα ενεργά στοιχεία του λογαριασμού σου.
3. Άνοιξε PowerShell μέσα στον νέο `cloudflare-worker/` και εκτέλεσε διαδοχικά:

```powershell
node --version
npm ci
npx wrangler whoami
npx wrangler deploy --dry-run --outdir ../worker-build-check
```

Αν χρειάζεται σύνδεση, χρησιμοποίησε `npx wrangler login`. Αν κάποια εντολή αποτύχει, μην συνεχίσεις στο deploy μέχρι να λυθεί το συγκεκριμένο σφάλμα.

4. Αφού ολοκληρωθούν τα backup και ο έλεγχος, ανέβασε στον ίδιο Worker:

```powershell
npx wrangler deploy
```

Η εντολή αυτή αλλάζει την ενεργή έκδοση. Κράτησε το νέο deployment/version ID που θα εμφανιστεί. Δεν χρειάζεται να δημιουργήσεις νέα D1 βάση ή buckets, να ξαναορίσεις PIN/κλειδιά, ή να τρέξεις `db:apply` γι' αυτή τη μετάβαση.

Ο Worker μαζί με τον φάκελο `public` αποτελεί ενιαία παράδοση. Το `dist/Fleet_Control_Web_Assets_v5.36.5.zip` είναι συμπληρωματικό αρχικό αρχείο της ίδιας έκδοσης· δεν απαιτείται δεύτερο ανέβασμα αλλαγμένου frontend γι' αυτή την ενημέρωση, εφόσον έχεις ήδη 5.36.5.

## 3. Ενημέρωση Android Server

Αφού ολοκληρωθεί το backup, σταμάτησε τον Server από το κουμπί του όταν δεν εκτελεί εργασίες. Εγκατέστησε το `dist/Fleet_Control_Server_v2.0.12.apk` ως ενημέρωση της ίδιας εφαρμογής. Το package name και το πιστοποιητικό υπογραφής ταιριάζουν, και το versionCode αυξάνεται από 14 σε 15.

**Μην κάνεις απεγκατάσταση ή εκκαθάριση δεδομένων.** Άνοιξε ξανά την εφαρμογή, έλεγξε ότι διατηρούνται Worker URL και φάκελος backup, και ξεκίνησε τον Server. Στις Ρυθμίσεις η παράλληλη επεξεργασία έχει εύρος 1–10 και προεπιλογή 4.

Πριν από μαζικό επανέλεγχο, δοκίμασε λίγα αντιπροσωπευτικά τιμολόγια. Σύγκρινε πινακίδα, ημερομηνία, ποσό, εργασίες και πλήθος συνημμένων με τα πραγματικά PDF. Επιβεβαίωσε επίσης εμφάνιση μηχανών, εργαζομένων και προγράμματος. Η απόδοση/ορθότητα της ανάγνωσης στο S24 Ultra δεν έχει ελεγχθεί από εμάς σε πραγματική συσκευή.

## 4. Αν η νέα έκδοση δεν λειτουργεί σωστά

### A. Πρόβλημα στον κώδικα Worker, με σωστά δεδομένα

Στο Cloudflare: Workers & Pages → ο υπάρχων Worker → Deployments → επίλεξε τη συγκεκριμένη προηγούμενη έκδοση → Rollback. Εναλλακτικά:

```powershell
npx wrangler rollback PREVIOUS_VERSION_ID
```

Χρησιμοποίησε το ID που κατέγραψες πριν το update. Η επιστροφή Worker αλλάζει τον κώδικα και δεν γυρίζει πίσω τη D1 ή τα R2 αρχεία. Ο φάκελος `previous-version/` περιέχει επίσης το παλιό πακέτο Web/Worker για νέα ανάπτυξη στον ίδιο Worker, αν χρειαστεί.

### B. Χρειάζεται ανάκτηση συγκεκριμένων παλιών δεδομένων από backup εφαρμογής

Σταμάτησε προσωρινά νέες εγγραφές/συγχρονισμούς και κράτησε πρώτα νέο ξεχωριστό αντίγραφο της τρέχουσας κατάστασης. Στον Server επίλεξε τον φάκελο που περιέχει το σωστό ζευγάρι `.fcbackup`/`.fcdocs`. Πήγαινε **Backup → Επαναφορά από αρχείο backup**, δώσε το τρέχον Admin PIN και διάλεξε το `.fcbackup`.

Η ολοκλήρωση της επαναφοράς προς Cloudflare χρειάζεται σύνδεση, σωστό Server key και Admin PIN. Έλεγξε το αποτέλεσμα και τα ίδια τα τιμολόγια· το μήνυμα επιτυχίας εγγραφών δεν εγγυάται επιτυχή μεταφόρτωση όλων των συνημμένων.

**Περιορισμοί που επιβεβαιώθηκαν στον κώδικα:**

- Οι πίνακες προσωπικού/βαρδιών/μισθοδοσίας εισάγονται με συγχώνευση (upsert). Εγγραφές που δημιουργήθηκαν μετά το backup μπορεί να παραμείνουν.
- Η τοπική λίστα στόλου επίσης συγχωνεύεται. Η διαδικασία δεν είναι ενιαίο ατομικό rollback της εγκατάστασης.
- Το `.fcbackup` δεν είναι πλήρες SQL dump: δεν περιλαμβάνει όλους τους βοηθητικούς πίνακες, sessions, ουρές και αντικείμενα R2.
- Η ανάγνωση κάθε `.fcbackup` ή `.fcdocs` περιορίζεται σε **50 MiB** (52.428.800 bytes). Μπορεί να δημιουργηθεί μεγαλύτερο archive που δεν θα γίνει δεκτό στην επαναφορά. Με πολλά PDF χρειάζεται ανεξάρτητο R2 backup.
- Το `.fcdocs` περιλαμβάνει μόνο τα υπάρχοντα τοπικά συνημμένα. Τα δύο αρχεία πρέπει να έχουν το ίδιο timestamp και να βρίσκονται στον σωστό επιλεγμένο φάκελο.

Έγινε επιτυχής τοπική δοκιμή εξαγωγής/εισαγωγής σε βάση μνήμης με εικονικά δεδομένα. Επιβεβαίωσε ότι επανέρχεται παλιά τιμή και παραμένει μεταγενέστερη εγγραφή. Δεν έγινε επαναφορά πραγματικού backup στο κινητό σου.

### C. Απαιτείται ακριβής επιστροφή της βάσης πριν το update

Αυτό χρειάζεται συντονισμένη διαδικασία: προσωρινή διακοπή νέων εγγραφών/Server, νέο backup της τρέχουσας κατάστασης, σωστό bookmark και συμβατά αρχεία R2. Ο τεχνικός που εκτελεί την ανάκτηση πρέπει να ελέγξει και τα τοπικά δεδομένα/εκκρεμείς συγχρονισμούς πριν ξαναενεργοποιήσει τις συσκευές, ώστε να μην ξαναγράψουν μεταγενέστερα δεδομένα.

Η D1 επαναφορά, μόνο όταν έχει επιλεγεί συνειδητά το σωστό σημείο, γίνεται με:

```powershell
npx wrangler d1 time-travel restore fleet-control-db --bookmark=YOUR_SAVED_BOOKMARK
```

Η εντολή αντικαθιστά τη βάση με την παλιά κατάσταση. Οι μεταγενέστερες αλλαγές δεν παραμένουν σε εκείνο το αποκατεστημένο αντίγραφο. Φύλαξε και το bookmark που επιστρέφεται για την κατάσταση πριν την επαναφορά. Η ανάκτηση SQL σε νέο περιβάλλον και η επαναφορά αρχείων R2 είναι χωριστές ενέργειες και χρειάζονται έλεγχο συνέπειας πριν συνδεθούν οι εφαρμογές.

Μην εκτελείς τυφλά `d1 execute --file` πάνω στην ενεργή μη κενή βάση· ένα SQL dump δεν είναι από μόνο του αυτοματοποιημένο ασφαλές rollback. Για ανακατασκευή από SQL, προτίμησε πρώτα ξεχωριστή βάση δοκιμών και έλεγξε τη σωστή σύνδεση/bindings πριν οποιαδήποτε μετάβαση.

### D. Επιστροφή Android Server σε παλιότερο κώδικα

Το Android αποτρέπει κανονική εγκατάσταση APK με μικρότερο versionCode. Το παλιό 2.0.11 (14) δεν εγκαθίσταται απλώς πάνω από το 2.0.12 (15). Το παλιό APK περιλαμβάνεται για αναφορά, όχι ως κουμπί άμεσης επιστροφής.

Μην απεγκαταστήσεις τον Server για να παρακάμψεις αυτόν τον έλεγχο. Μια διορθωτική έκδοση με ίδιο κλειδί και μεγαλύτερο versionCode μπορεί να διατηρήσει τα δεδομένα. Εναλλακτική καθαρή επανεγκατάσταση χρειάζεται πρώτα επιβεβαιωμένα πλήρη backup και σχεδιασμό επαναφοράς. Δεν κατασκευάστηκε τέτοιο rollback APK σε αυτή την παράδοση.

## 5. Τι έχει ελεγχθεί

- Αμετάβλητα αρχικά APK και Worker πακέτα, με SHA-256.
- Πλήρες build Client/Server με την εργαλειοθήκη που περιλαμβάνεται στο πακέτο ανάπτυξης. Τα περιεχόμενα εφαρμογής, μαζί με τα `classes.dex`, ταυτίζονται με τα αρχικά APK.
- Επιτυχές `wrangler deploy --dry-run` για τον νέο Worker, χωρίς deploy.
- Τοπικές δοκιμές στόλου, προγράμματος, μισθοδοσίας και προσομοιώσεις διαχείρισης.
- Πρόσθετη δοκιμή εξαγωγής/επαναφοράς εικονικών δεδομένων, με καταγραφή των ορίων της συγχώνευσης.

Δεν ελέγχθηκε η ενεργή εγκατάστασή σου, δεν λήφθηκαν πραγματικά backup και δεν έγινε δοκιμή σε Android συσκευή. Η δοκιμή browser του έργου είχε παραλειφθεί επειδή δεν υπήρχε εγκατεστημένο Chromium.
