# Πρόγραμμα εβδομάδας — 5.51.10, issue #17

## Πρόβλημα και αιτία που αναπαράχθηκε

Στις 28/10/2026 ο χρήστης έδωσε δύο production logs της ίδιας έκδοσης Worker:
POST αποθήκευσης και GET εβδομάδας 2026-10-26 με HTTP 503, `exceededCpu`, CPU
10 ms. Το GET απέτυχε και σε Web, ενώ το POST προερχόταν από Client APK.
Δεν είναι γνωστό αν το αρχικό production POST ολοκλήρωσε εγγραφή.

Μετρήθηκε ο πλήρης Worker με συνθετική εβδομάδα 60 εργαζομένων × 7 ημερών:
η παλιά αποθήκευση έκανε 3.432 `Intl.formatToParts`, η φόρτωση Προχείρου 14.592,
η αντικατάσταση εβδομάδας ενός διανομέα 6.736 και η δημοσίευση 13.529.
Η φόρτωση δημοσιευμένου προγράμματος δημιουργούσε επιπλέον 840 formatters.
Το τοπικό CPU profile έδειξε συγκέντρωση δειγμάτων στις κλήσεις ICU/formatter.
Τα στοιχεία baseline αποθηκεύονται στο `issue-17-cpu-baseline.json`.

Σημεία υπερβολικής εργασίας:

- Κάθε επικύρωση τμημάτων προτύπου μετέτρεπε μια σταθερή ημερομηνία σε UTC,
  ακόμη και για τον απλό έλεγχο επικάλυψης ωρών.
- Ίδιες ημερομηνίες/ώρες/ζώνες μετατρέπονταν ξανά για κάθε διανομέα και φάση.
- Το localClock δημιουργούσε νέο Intl.DateTimeFormat για κάθε ώρα κάθε γραμμής.
- Η GET διαμόρφωνε το δημοσιευμένο πρόγραμμα ακόμη κι όταν στη συνέχεια το
  αντικαθιστούσε ολόκληρο με το Πρόχειρο.
- Οι έλεγχοι σύγκρουσης αναζητούσαν κάθε φορά σε όλες τις αναθέσεις.

Αυτά αποτελούν αναπαραγμένο CPU bottleneck συμβατό με τα production συμπτώματα.
Δεν λήφθηκε production profile ούτε το ακριβές request body/αποθηκευμένο πρόγραμμα
του χρήστη. Οι τοπικοί χρόνοι SQLite/Node **δεν είναι** Cloudflare production CPU
και το τοπικό Workerd δεν επιβάλλει το production όριο. Απαιτείται τελική
επιβεβαίωση της πραγματικής εβδομάδας μετά την ενεργοποίηση.

## Διόρθωση

- Έλεγχος τμημάτων προτύπου με ακέραια λεπτά, με διατήρηση της προηγούμενης
  νυχτερινής/σπαστής λογικής και των ελέγχων επικάλυψης.
- Περιορισμένες caches (1.024 στοιχεία ανά cache) μόνο για καθαρές συναρτήσεις
  ημερομηνίας/ώρας/ζώνης. Δεν αποθηκεύονται δικαιώματα, χρήστες ή δεδομένα βάσης.
  Η αλλαγή timezone είναι μέρος του κλειδιού. Η έξωση δεν αλλάζει το αποτέλεσμα.
- Διακοπή της επαναληπτικής μετατροπής όταν επιτευχθεί το ίδιο ακριβές σταθερό
  σημείο. Διατηρούνται οι 4 επαναλήψεις όπου δεν υπάρχει σύγκλιση, ώστε να μη
  μεταβληθεί η προηγούμενη πολιτική αμφίσημων/ανύπαρκτων ωρών DST.
- Το localClock χρησιμοποιεί τον κοινό formatter και τις ίδιες μετατροπές.
  Δεν υπολογίζεται η αγνοούμενη δημοσιευμένη εμφάνιση όταν υπάρχει Πρόχειρο.
- Δείκτες ανά εργαζόμενο/μηχανή για τους ελέγχους σύγκρουσης, με την ίδια σειρά
  προτεραιότητας και διατήρηση όλων των προηγούμενων κανόνων.
- Σύγκριση του ακριβούς Προχείρου/updated_at και revision δημοσίευσης πριν την
  εγγραφή. Ταυτόχρονη αλλαγή απορρίπτεται ως 409, χωρίς αντικατάστασή της.
- Αποθήκευση Προχείρου και σχετικού audit στο ίδιο D1 batch. Αποτυχία audit
  αναιρεί την εγγραφή. Σε stale write δεν δημιουργείται ψευδές audit επιτυχίας.
- Web/Client: επίμονο μήνυμα αποτυχίας φόρτωσης, σαφής διάκριση από κενή εβδομάδα,
  κουμπί επανάληψης ανάγνωσης και απενεργοποίηση ενεργειών σε παλιά προβολή.
  Αγνοούνται καθυστερημένες αποκρίσεις προηγούμενης εβδομάδας/σύνδεσης.
- Αποτυχία POST διατηρεί τη συμπληρωμένη φόρμα και δεν κάνει αυτόματο replay.
  Επιτυχές POST με αποτυχημένο επόμενο GET αναφέρεται ως αποθηκευμένο Πρόχειρο
  με αποτυχία ανανέωσης, χωρίς να ζητά δεύτερη αποθήκευση.

## Έλεγχοι και τεκμήρια

- Πλήρες `scripts/check-all.sh` με υπάρχοντα migrations, backup, payroll,
  schedule/template/vehicle και invoice regressions.
- `test-schedule-cpu.mjs`: 378 ανεξάρτητες συγκρίσεις με τον παλιό αλγόριθμο,
  6 ζώνες, θερινές/χειμερινές/ανύπαρκτες ώρες, Lord Howe μισή ώρα και Apia
  παράλειψη ημέρας. Ακόμη 1.100 περιπτώσεις έξωσης cache και επικύρωση εισόδων.
- Πλήρης Worker + SQLite με 420 αναθέσεις, save/load/replace/publish/load,
  όριο 500 κλήσεων ICU ως deterministic regression εργασίας, όχι ως υπόσχεση
  production χρόνου. Παλιός κώδικας υπερβαίνει αυτό το όριο. Νέο save 36 κλήσεις,
  επόμενες αναγνώσεις/αντικαταστάσεις ίδιων ορίων 0, publish 1.
- Πραγματικό τοπικό Workerd/D1 με τον πλήρη Worker, 420 αναθέσεις, όλες τις
  αντίστοιχες λειτουργίες και injected audit failure: επιβεβαιωμένο rollback
  και σωστό audit επιτυχίας. Έλεγχος stale concurrent edit στο SQLite harness.
- Chromium Web desktop/mobile και file Client tablet: αρχικό GET 503, επιτυχής
  επανάληψη, διατήρηση φόρμας στο POST 503, ακριβώς ένα POST ανά υποβολή,
  επιτυχημένη εγγραφή με αποτυχία ανανέωσης, παλιά απόκριση που φτάνει αργότερα.
- `profile-schedule-cpu.mjs`: αναπαραγώγιμο Node CPU profile και operation counts
  στο `verification/schedule-cpu/`. CI artifact μαζί με screenshots/results.
- Πλήρες GitHub CI και builds ακριβούς source πριν τη δημοσίευση. Τα ακριβή
  source SHA, runs, ενεργοποίηση και live checks καταγράφονται στο PR/handoff.

Δεν διαγράφηκε/αναδημιουργήθηκε πραγματικό πρόγραμμα, δεν έγινε τυφλή
επανυποβολή του αρχικού POST, παραγωγική δοκιμαστική μεταβολή ή νέο backup/restore.
Δεν ελέγχθηκε εγκατάσταση σε φυσική συσκευή. Δεν αυξήθηκε κόστος/συνδρομή.

## Έκδοση και επαλήθευση χρήστη

Client/Web 5.51.10, Client versionCode 82, Worker 5.12.10. Server παραμένει
2.2.15 / code 41. Διατηρούνται τα παλιά immutable assets και η συμβατότητα
υπαρχόντων clients. Το APK παραγωγής υπογράφεται μόνο από το κανονικό workflow
με το αρχικό κλειδί. Τα CI APK χρησιμοποιούν προσωρινό κλειδί.

Μετά την ενεργοποίηση, ο χρήστης ανοίγει πρώτα την εβδομάδα 26/10–1/11 και
ελέγχει τι υπάρχει πραγματικά αποθηκευμένο πριν κάνει νέα αλλαγή. Ελέγχεται
φόρτωση, μια κανονική αλλαγή και εκ νέου φόρτωση σε Web/Client. Αν αποτύχει,
συλλέγονται endpoint/ώρα/ray/outcome/CPU. Το #17 μένει ανοιχτό μέχρι αυτή την
production επιβεβαίωση· νέο publish δεν απαιτείται μόνο για την καταγραφή της.
