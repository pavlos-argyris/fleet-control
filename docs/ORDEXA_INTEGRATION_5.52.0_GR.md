## Αρχιτεκτονική και όρια πρόσβασης

Η σύνδεση, τα διαπιστευτήρια και η άντληση/προετοιμασία ημερήσιων αναφορών
γίνονται στο **Server APK**. Ο κωδικός χρησιμοποιείται για login και δεν
αποθηκεύεται. Η συνεδρία αποθηκεύεται κρυπτογραφημένη με AndroidKeyStore σε
χωριστές ιδιωτικές προτιμήσεις και δεν εξάγεται στα backup ή στο Cloudflare.
Μετά από νέα συσκευή/απώλεια κλειδιού/λήξη συνεδρίας χρειάζεται νέα σύνδεση.

Επιτρέπονται μόνο σταθερό HTTPS origin api.ordexa.gr, POST login και οι
συγκεκριμένες GET αναγνώσεις me/cities/report. Δεν υπάρχει γενικό proxy,
προσαρμοζόμενο URL ή ακολούθηση redirects. Άλλες ενέργειες απορρίπτονται πριν
αποστολή. Καμία αλλαγή δεδομένων/ωραρίων/μισθοδοσίας/δικαιωμάτων στο Ordexa.

Η διεπαφή προκύπτει από τον δημόσιο client του παρόχου και τις πραγματικές
οθόνες. Δεν έχει επιβεβαιωθεί ως υποστηριζόμενο δημόσιο API τρίτων ή η ύπαρξη
ρόλου μόνο ανάγνωσης. Οι πραγματικοί περιορισμοί/σταθερά IDs ανεξάρτητου
Server login και τυχόν αλλαγές του σχήματος απαιτούν επαλήθευση στη συσκευή.
Ο connector σταματά σε άγνωστο/μη πλήρες σχήμα αντί να υποθέτει τιμές.

Ο Server στέλνει μόνο απαραίτητα rider IDs/ονόματα και αρχικές παρουσίες· δεν
στέλνει provider token, κωδικό, οικονομικά σύνολα ή αμοιβές Ordexa. Τοπικά
αποτυπώματα αποτρέπουν επαναποστολή αμετάβλητων αναφορών. Ο αυτόματος έλεγχος
είναι ανά ώρα για τις τελευταίες7ημέρες, μόνο αφού ενεργοποιηθεί από διαχειριστή.
Για παλιότερες διορθώσεις/ιστορική εισαγωγή υπάρχει ρητός έλεγχος περιόδου.
Ο Worker παραμένει υπεύθυνος για δικαιώματα, bounded validation/SQL αποθήκευση,
αντιστοίχιση και τον υφιστάμενο μηχανισμό μισθοδοσίας Fleet. Δεν υπόσχεται
μηδενικό CPU/requests. Τα τυχόν vendor rate limits δεν έχουν τεκμηριωθεί.

## Αρχική ρύθμιση

1. Ενημέρωσε και Server και Client πάνω από τα υπάρχοντα APK, χωρίς
   απεγκατάσταση/εκκαθάριση. Ανανέωσε το Web. Χρησιμοποίησε μόνο τα κανονικά
   υπογεγραμμένα APK του τελικού release, όχι τα test-signed artifacts CI.
2. Server → Ρυθμίσεις → Σύνδεση παρουσιών Ordexa. Σύνδεση λογαριασμού,
   επιλογή πόλης και αποθήκευση. Η πρόσβαση browser αυτής της συνομιλίας
   δεν μεταφέρεται στη συσκευή ή στο Fleet.
3. Προεπισκόπηση μιας γνωστής ημέρας: επιβεβαίωσε πλήθος/διανομείς χωρίς
   αποθήκευση. Μετά συγχρονισμός της επιλεγμένης περιόδου στο Fleet.
   Ημερήσιες αναφορές υποβάλλονται διαδοχικά, με στάδιο και αποτέλεσμα.
4. Client/Web → Ρυθμίσεις → Σύνδεση εργαζομένων. Για κάθε όνομα Ordexa διάλεξε
   ρητά τον αντίστοιχο υπάρχοντα εργαζόμενο Fleet. Τα ονόματα μπορεί να είναι
   τελείως διαφορετικά. Επιβεβαιώνονται και τα δύο ονόματα και αιτιολογία.
   Η σύνδεση κρατά cityId/riderId/Fleet ID, παραμένει μετά από μετονομασία και
   δεν δημιουργεί εργαζόμενο. Δεν αποθηκεύεται αυτόματη πρόταση ονόματος.
5. Κανόνες συνέχειας: όρισε ο ίδιος όριο κενού 0–240 λεπτά και αν το κενό
   προσμετράται ή εξαιρείται. Το0δεν ενώνει χωριστές μη επικαλυπτόμενες
   παρουσίες. Οι αρχικές καταγραφές παραμένουν αυτούσιες, ανεξάρτητα από
   την υπολογισμένη ομαδοποίηση. Δεν υπάρχει αρχική επιχειρησιακή προεπιλογή.
6. Αφού ελεγχθούν τα δεδομένα, επίλεξε Πηγή ωρών μισθοδοσίας → Ordexa.
   Η επιλογή επηρεάζει ανοικτές περιόδους. Fleet clock/schedule παραμένουν
   διαθέσιμες χωριστές πηγές· δεν αθροίζονται με Ordexa. Δεν απαιτείται
   δημοσιευμένο πρόγραμμα ή Fleet login κάθε διανομέα για εισαγωγή παρουσιών.

## Έλεγχοι, διορθώσεις και συγχρονισμός

- Ατομική αποθήκευση ημερήσιας αναφοράς/receipt/ονόματος/παρουσιών. Παλιά ή
  διπλή υποβολή δεν αντικαθιστά νεότερη, αποτυχία δεν δηλώνεται επιτυχία.
- Χωριστές αρχικές αναγνώσεις και τρέχουσες παρουσίες. Δεν διαγράφονται
  καταγραφές επειδή η νέα αναφορά ήταν κενή/ελλιπής ή μια παρουσία λείπει.
  Η εξαφάνιση επισημαίνεται. Αλλαγή ολοκληρωμένης παρουσίας απαιτεί έλεγχο.
- Χωρίς σταθερό event ID χρησιμοποιείται ελεγχόμενη ταυτότητα από πόλη,
  riderId και πλήρες αρχικό clock in. Αλλαγή clock in μπορεί να παράγει
  νέα εγγραφή και παλιά εξαφανισμένη· η εκκρεμότητα εμποδίζει σιωπηλή πληρωμή.
- Αποδοχή ή μη προσμέτρηση με αιτιολογία αφορά μόνο το Fleet. Τα raw δεδομένα,
  προηγούμενη έκδοση και audit διατηρούνται. Η νέα ανάγνωση ίδιων δεδομένων
  δεν αναιρεί ήδη καταγεγραμμένη απόφαση.
- Ελλιπής έξοδος, μη αντιστοιχισμένος εργαζόμενος, απουσία ημέρας ή ανεπίλυτη
  διαφορά εμφανίζεται ως blocker πριν από κλείδωμα μισθοδοσίας. Οι συνολικές
  «Ώρες» του Ordexa δεν χρησιμοποιούνται αντί των inAt/outAt.
- Υφιστάμενες ωριαίες ζώνες/στρογγυλοποιήσεις Fleet διατηρούνται. Τα κενά
  εξαιρούνται χωρίς δεύτερη στρογγυλοποίηση αρχής μετά από επανασύνδεση.
  Επικαλυπτόμενες παρουσίες δεν προσμετρώνται δύο φορές.
- Κλειδωμένη περίοδος χρησιμοποιεί την αποθηκευμένη πηγή/ποσά/κανόνες.
  Αναθεώρηση παρουσίας που έχει ήδη πληρωθεί σε άλλη κλειδωμένη περίοδο
  χρειάζεται πρώτα έλεγχο της προηγούμενης μισθοδοσίας. Δεν προστίθεται
  σιωπηρά δεύτερη πληρωμή. Revision guard αποτρέπει κλείδωμα παλιού υπολογισμού.
- Όρια: ημερήσια αναφορά έως200διανομείς/2000παρουσίες και κανονικοποιημένο
  payload έως1MiB, provider response έως8MiB, ρητή περίοδος έως31ημέρες,
  προεπισκόπηση λίστας με σελίδες200παρουσιών και ένδειξη συνέχειας.
- Τα ordexa_riders/imports/sessions περιλαμβάνονται σε backup/mirror/restore.
  Ελεγχόμενη αλλαγή mirror epoch απαιτεί μία νέα πλήρη λήψη για τους νέους
  πίνακες. Παλιά backup δεν διαγράφουν νεότερα δεδομένα Ordexa.
- OTA: καταγραφή τρέχοντος σταδίου, ασφαλής παύση ανάμεσα στις ημέρες,
  διατήρηση επιβεβαιωμένων ημερών και επανάληψη μετά την ενημέρωση.

## Πραγματική επαλήθευση και παράδοση

Αρχική πραγματική σύνδεση/ορατές παρουσίες browser επαληθεύτηκαν χωρίς αλλαγή
Ordexa. Κώδικας/σταθερές διαδρομές ελέγχθηκαν στον δημόσιο client. Πέρασαν
συνθετικές δοκιμές Java protocol/fences, Worker/D1 auth/CAS/replay/rollback,
διαφορετικά ονόματα/μετονομασία, DST, κενά/παλιές αποφάσεις και UI dialogs.
Το πλήρες CI, browser/native/backup/προηγούμενες λειτουργίες και ακριβή
checkpoints/ενεργοποίηση καταγράφονται στα επόμενα ορόσημα του handoff.

Δεν έγινε εισαγωγή παραγωγικών παρουσιών, μεταβολή/κλείδωμα πραγματικής
μισθοδοσίας, backup/restore ή εγκατάσταση σε φυσικό Android από τον βοηθό.
Τα issues παραμένουν ανοιχτά μέχρι πραγματική επαλήθευση συσκευής/δεδομένων.
Πλήρης πηγή όλων των τμημάτων, APK/Web/Worker, dependencies/build inputs,
οδηγίες και SHA-256 από το τελικό GitHub Release. Τα παλιά immutable assets
και οι αρχικές υπογραφές διατηρούνται. Δεν χρειάζονται νέα κλειδιά ή υπηρεσία.
