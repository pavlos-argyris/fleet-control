# Server 2.10.19 — πόροι της ενσωματωμένης JavaScript

Η [5.61.1 / Server 2.10.19](https://github.com/pavlos-argyris/fleet-control/releases/tag/fleet-v5.61.1) δημοσιεύτηκε επιτυχώς. Ο [τελικός έλεγχος](https://github.com/pavlos-argyris/fleet-control/actions/runs/42419857010) επαλήθευσε τις αρχικές υπογραφές, τους πόρους του πραγματικού APK και τα ληφθέντα bytes. Η φυσική εγκατάσταση/επανάληψη της μεταφοράς στη συσκευή είναι το επόμενο βήμα του ιδιοκτήτη.

## Πραγματικό περιστατικό

Μετά την εγκατάσταση Server 2.10.18, ο ιδιοκτήτης προχώρησε στη μεταφορά της
κύριας βάσης και ανέφερε `Can't find bundle for base name
org.mozilla.javascript.resources.Messages, locale en_US`.
Το δημοσιευμένο APK με SHA-256
`6b9f7c4ba84eeae7842560a6f5bec04c204db201bf61fb23b2b47d8e7634dc77`
δεν περιλαμβάνει τα μηνύματα Rhino ούτε τη δήλωση `RegExpLoader`.
Η δημόσια περιγραφή έδειξε `mode=preparing`, όχι ενεργή native βάση.

Το custom build μετέτρεπε τις κλάσεις των dependency JAR σε DEX, αφού πρώτα
αφαιρούσε όλους τους υπόλοιπους πόρους. Οι προηγούμενες JVM δοκιμές έβρισκαν
τους πόρους στο πλήρες dependency JAR και δεν ανίχνευαν αυτό το κενό του APK.

## Διόρθωση και επαλήθευση

Η προετοιμασία αντιγράφει από το αρχικό, SHA-256 επαληθευμένο Rhino JAR τους
πόρους Java πριν αφαιρεθούν οι κλάσεις για DEX. Στη συνέχεια προστίθενται στη
ρίζα του APK, ώστε να είναι διαθέσιμοι στο κανονικό Java classpath. Περιλαμβάνεται
και το `META-INF/services/org.mozilla.javascript.RegExpLoader`. Τα παλιά JAR
manifests/υπογραφές δεν μεταφέρονται και η κανονική υπογραφή APK παραμένει.

Το `scripts/test-business-runtime-resources.mjs` απομονώνει τις Rhino κλάσεις
σε JAR χωρίς κανέναν πόρο. Μόνο το ελεγχόμενο APK παρέχει ResourceBundle και
ServiceLoader δεδομένα. Εκτελεί πραγματική JavaScript/JSON, κανονικές εκφράσεις
μέσα στο sandbox και σφάλμα σύνταξης με αναγνώσιμο μήνυμα. Ελέγχει US, FR, CN
και Greek locale fallback και συγκρίνει τα ακριβή bytes και των πέντε πόρων.
Ξεχωριστές αρνητικές περιπτώσεις καλύπτουν πλήρη απουσία πόρων και μηνύματα
χωρίς πάροχο κανονικών εκφράσεων.

Ο έλεγχος καλείται πριν/μετά την κατασκευή στο πλήρες CI και πάνω στα πραγματικά
υπογεγραμμένα APK από το `verify-apks.mjs` πριν από δημοσίευση. Τα αποτελέσματα
της τρέχουσας εκτέλεσης καταγράφονται στο κοινό handoff/PR. Η δοκιμή JVM με
πόρους πραγματικού APK δεν παρουσιάζεται ως φυσική εγκατάσταση Android.

## Συνέχεια στη συσκευή μετά τη δημοσίευση

1. Αν η αποτυχημένη μεταφορά έχει μείνει σε αναμονή και εμποδίζει καταχωρίσεις,
   Server → Ρυθμίσεις → Κύρια βάση Server → Ακύρωση μεταφοράς, με την αντίστοιχη
   επιβεβαίωση, επαναφέρει την προηγούμενη cloud λειτουργία. Αυτή είναι ενέργεια
   της ελεγχόμενης ροής Server και διατηρεί το τοπικό αντίγραφο/backup.
2. Εγκατάσταση του συμβατού Server 2.10.19 πάνω στην υπάρχουσα εφαρμογή.
   Client/Web 5.61.0 συνεχίζουν να είναι η συμβατή έκδοση.
3. Ρυθμίσεις → Κύρια βάση Server → Μεταφορά και έλεγχος ή Συνέχεια μεταφοράς,
   ανάλογα με την πραγματική αποθηκευμένη κατάσταση.
4. Η επιτυχία δηλώνεται μόνο όταν εμφανιστεί «Η κύρια βάση λειτουργεί σε αυτόν
   τον Server», αφού περάσουν σύγκριση, πλήρες backup και δοκιμή ανάκτησης.

Η διόρθωση δεν παρακάμπτει επιβεβαίωση ιδιοκτήτη, μεταφορά δεδομένων, δικαιώματα,
backup ή τους οικονομικούς κανόνες. Η εγκατάσταση δεν εκτελεί παραγωγικό restore.
