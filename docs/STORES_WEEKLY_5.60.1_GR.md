Χρησιμοποιούνται αποκλειστικά οι ήδη δημοσιευμένοι Server-first ημερήσιοι υπολογισμοί, σε cents, με ημέρα05:00–05:00 Europe/Athens. Ανά50 επιλεγμένα καταστήματα ένα read-only report αίτημα· όλες οι σελίδες δεσμεύονται στο ίδιο αποτύπωμα σύνδεσης/όρων/δημοσιεύσεων, αλλιώς απορρίπτονται. Οι 7 ημέρες εμφανίζονται ακόμη και χωρίς λήψη, με άγνωστα ποσά αντί για ψευδή0€.

2 παραγγελίες ×2€ με ελάχιστο10€: έσοδα4€, συμπλήρωμα6€, σύνολο10€. Με0 παραγγελίες το συνήθες συμπλήρωμα είναι0€. Η παλαιότερη χωριστή ρητή επιλογή `chargeOnZero=true` δεν αλλάζει σιωπηρά: αν παράγει χρέωση σε μηδενική ημέρα, η νέα αναφορά επισημαίνει ασυμβατότητα και εκκρεμές ποσό, ζητώντας έλεγχο της επιλογής. Δεν μεταβάλλει τα αποθηκευμένα οικονομικά δεδομένα. Απουσία όρων, ασυμφωνία ισχύουσας έκδοσης/διατήρησης, εκκρεμής έλεγχος πηγής ή ελλιπής ημέρα σημαίνει μη οριστικό/άγνωστο συνολικό ποσό. Η παλιότερη λήψη και η ώρα δημιουργίας δηλώνονται ρητά. Τα αποθηκευμένα στιγμιότυπα δεν τροποποιούνται από προβολή/εκτύπωση.

## Audit και συμβατότητα backup

Δεν δημιουργείται δεύτερο ledger ή πίνακας. Οι νέες πραγματικές αλλαγές `unitPriceCents`, `dailyMinimumCents`, `chargeOnZero` αποθηκεύουν προαιρετικό `audit` μέσα στο νέο append-only record `kind=terms` του υπάρχοντος `store_billing_records`/`store_billing_local`. Περιέχει schema1, operationId, actor ID/όνομα/ρόλο, recordedAt, χωριστό effectiveDay, previousTermsId και changes με πραγματική παλιά/νέα τιμή. Το ίδιο atomic CAS transaction γράφει per-store global audit και όρους. No-op δεν δημιουργεί νέα terms ή financial audit. Retention διατηρεί δικό της audit. Retry ίδιας ενέργειας δεν διπλασιάζει καταγραφή· stale revision απορρίπτει όλη τη συναλλαγή.

Τα παλιά records μένουν ανέπαφα και δεν αποκτούν επινοημένα γεγονότα. Αναγράφεται «Δεν υπάρχει διαθέσιμο παλιότερο ιστορικό». Το ιστορικό εμφανίζεται νεότερο πρώτο ανά30, με cursor δεσμευμένο στο κατάστημα/ενεργό scope. Read-only χρήστες το βλέπουν στην καρτέλα καταστήματος· managers και στις ρυθμίσεις. Στην αναφορά επιλέγονται γεγονότα βάσει ημερομηνίας ισχύος, όχι ημερομηνίας καταχώρισης, άρα περιλαμβάνονται μεταγενέστερες αναδρομικές αλλαγές. Προϋπάρχοντες όροι εμφανίζονται ως αφετηρία, superseded γεγονότα χωρίς εφαρμογή σε ημέρα της εβδομάδας δεν δηλώνονται ως οικονομική επίδραση.

Η αλλαγή είναι additive JSON, χωρίς SQL schema migration ή μετατροπή παλιών δεδομένων. Ο υφιστάμενος συγχρονισμός inputs και native backup/restore μεταφέρουν αυτούσιο το audit μαζί με τους όρους. Ο Server επικυρώνει το optional schema πριν από restore. Παλιότερα backup χωρίς audit παραμένουν έγκυρα. Οι υπάρχοντες κανόνες restore/source-refresh και προστασίας δεδομένων παραμένουν. Source ZIP δεν αποτελεί backup παραγωγής· δεν έγινε πραγματικό παραγωγικό backup/restore.

## API / επικαλύψεις μεγάλου5.61

- `GET /api/admin/store-billing/weekly-report?from=Monday&ids=[...]&snapshot=...`: `stores.view`, snapshot/from/to/stores/days/terms/generatedAt.
